# P1-4 人工阶段控制与时间

实施基线为 GitHub `main` 的 `c023263`。赛事阶段与报名开关分别由管理员操作，计划日期和待办只提供提示。

## 阶段准入

| 动作 | 角色与归属 | 本届的准入条件 | 已归档或归属待核对 |
|---|---|---|---|
| 注册账号 | 未登录用户 | 有活跃赛季、至少一条启用赛道，且管理员开放报名 | 无活跃赛季时关闭 |
| 建队、邀请、取消邀请、处理入队申请、分配位置 | 本届队长和自己的队伍 | 报名有效开放，继续校验人数、待处理状态及队伍归属 | 普通写入关闭 |
| 申请入队、接受或拒绝邀请、选赛道 | 选手或队长，操作自己的邀请、申请或成员记录 | 报名有效开放，继续校验成员身份、满员状态、赛道启用状态及人数限制 | 普通写入关闭 |
| 编辑当前赛道、队伍与成员配置 | 管理员，限本届配置 | 开赛后仍可修改。新选赛道必须启用，已有比赛继续使用规则快照 | 经允许的历史纠错走 P0-5 |
| 启动赛事、执行匹配、结束赛事、恢复报名 | 管理员 | 手动推进报名 → 匹配 → 进行中 → 已结束。开赛、匹配和恢复报名须有启用赛道，开赛另查队伍资格。恢复报名同时打开开关 | 换季按 P0-4 |
| 手动排赛、拆分、改时间、确认排赛和删除 | 管理员，限本届整场及其时段 | 本届未手动结束。确认、重拆、改日程和删除还受整场既有成绩或结果保护 | 普通写入关闭 |
| 协商和确认日期 | 本届整场双方选手 | 待排期或待确认，且本届未手动结束。任一方改时间后双方须重新认可 | 普通写入关闭 |
| 提交成绩和截图、弃权、补交 | 本届整场双方选手 | 整场状态允许且有提交资格。赛事手动结束后，仍可处理符合条件的已安排比赛 | 普通写入关闭 |
| 确认结算、审核、改结果、人工调整分 | 管理员，限本届整场或成员 | 按既有结算状态、资料、原因和审计要求。赛事结束后仍可收尾 | 经允许的历史纠错走 P0-5 |

关闭报名后，可以查看已有申请、邀请、队伍和赛程。开赛时保持原报名开关。无启用赛道时仍可备份并换季，新一届的报名开关保持关闭。普通换季检查未结算整场，强制换季须填写原因。

## 时间与升级

- `EVENT_TIMEZONE` 默认 `Asia/Shanghai`，原生运行可通过环境变量配置，SQLite 和 MySQL 的 Compose 配置均读取该变量。
- 报名和比赛的计划窗口、经选手协商或后台填写的新排赛时间均按赛事时区录入，以 UTC 写入数据库，再按赛事时区展示。个人可用时段是相对的时段偏好。手动结束只改变阶段并记录审计时间。
- 日期可留空。完整区间的结束时间必须晚于开始时间，跨日有效。达到截止时刻会产生提示。存在夏令时歧义或缺失的当地时刻需要另选。
- schema 2 为计划窗口和排赛时间增加时区确认标记。旧无时区值原样保留，显示待核对。管理员通过「赛事设置」确认旧窗口后可重存为 UTC。旧排赛时间在后台重设后按新口径保存。换季按选择原样复制时间和标记，预览及换季后提示缺失、过期、倒置或旧值待核对。
- 升级前先用原版本生成备份，在隔离副本安装依赖后运行 `python -m flask --app 'app:create_app()' prepare`。原版本和 schema 1 的备份保留用于恢复核对。

## 验证

SQLite 与隔离的 MySQL Community Server 8.0.46 全套回归合计 144 项通过、1 项跳过。跳过的是 MySQL 下的 SQLite WAL 专属用例，该用例在 SQLite 上通过。P1-4 的 8 个专项分别在两种数据库运行，合计 16 项通过。

覆盖直接请求、开关和启用赛道、空白换季、待办提示、赛后补交与审核、跨日与夏令时边界、旧日期核对、版本 1 到版本 2 的备份迁移和保留。容器复验列在 P3-7。
