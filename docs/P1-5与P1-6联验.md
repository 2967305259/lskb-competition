# P1-5 与 P1-6 联验

基线为 GitHub `main` 的 `1e6ed57`。

| 口径 | 实现与验收 |
|---|---|
| 名次 | 队伍按积分降序，同分共享名次并占位。例如 100、100、90 分的名次为 1、1、3。首页、赛事大厅、后台、归档和 Excel 使用同一名次。 |
| 晋级 | 用名额线分数计算实际晋级集合。配置 4 名时，积分 100、90、80、70、70、70 的六队全部晋级。后台与大厅分别显示配置名额和实际队伍数。归档使用该届保存的名额，缺失时标记待核对。 |
| 场次、胜负与结算 | 统计以正式整场为单位。弃权时胜负已定，双方成绩满足条件并经管理员确认后计入已结算。审核驳回保留既有结果和积分。强制归档的未结算场次显示冻结。 |
| 战绩接口 | 继续提供原有 `total_matches`（已判胜负），并提供 `formal_matches`、`decided_matches`、`settled_matches`。胜、负、平场数口径沿用正式整场结果。 |
| Excel | 保留四个工作表和「队伍积分榜」原有 A–E 列。右侧附配置名额、实际晋级数及三项场次统计。队员表对照比赛累计、有效调整与榜单记录，历史资料缺失的明细显示待核对。 |
| 调整分 | 比赛累计 1000，加 10 分再乘 500，队伍积分为 505000。撤销后为 500000。改变本届倍率时同步重算，验收覆盖往届 500 倍、新届 100 倍的隔离。 |
| 历史核对 | 通过 `data-report` 确认历史赛季归属、分段、倍率和结算依据。有差额时保留原榜单值并显示待核对。 |

联验包含手动排赛生成分段、已有比赛重新拆分、有效零分、弃权待补交、重复提交和结算、审核驳回、调整分撤销、审计失败回滚、重复重算和归档保护。

SQLite 与 MySQL 8.0.46 全套回归共 150 项通过、1 项跳过，跳过项为 SQLite WAL 用例的 MySQL 参数。资料页和积分配置说明收尾后，P1-3、P1-6 和本次联验专项合计 22 项通过。
