# 明日方舟集成战略赛事网站改造最终参考

整理日期：2026-11-16。核对基线为工作区 `1db9564`（P1-2）及用户随后选定的五项补充任务。本文件用于安排后续开发、跟踪进度和验收。

## 1. 目标与范围

让每届《明日方舟》集成战略比赛都能复用同一套网站。组织者通过配置赛事名称、赛道、难度、队伍、时间、规则和素材即可办新一届，账号可跨届使用，往届成绩、规则和证据可查。单实例只运营一个活跃赛季，需要并行办赛时部署独立实例。赛制沿用本项目的集成战略赛道与队伍模型。

以下决策继续生效，详见原建议第 11 章。

- 注册后直接可用。用户审核、公告和站内通知退出流程。赛事名以 `Tournament.name` 为准。
- 管理员手动控制报名和阶段。日期用于提示，原样继承。开赛后有权限的人员可继续调整本届配置。
- 分时对阵按整场统计和结算。普通比赛确认结束后计分。弃权即时记胜负，待资料齐备并确认后计分。轮空无比赛记录、分数或战绩。审核驳回保留已记积分和胜负。
- 晋级线同分全部晋级。队伍并列名次占位并跳号，例如 1、1、3。人工调整计入队员积分后，再乘该届队伍倍率。
- 往届普通入口只读。符合条件的超管纠错使用该届快照、填写原因并审计。可强制换季，须记录理由与未结算清单，原状态保留，普通写入冻结。确有缺失的历史资料列入人工核对。
- 归档冻结赛事规则、赛道名称和赛制，昵称、头像随账号更新。截图和日志默认保留，清理由管理员手动触发，`ScoreLog` 永久保留。备份批次另行保留。

P4 计分器集成、P5 计分器规则封堵和表演赛专项继续暂缓。正式成绩沿用手填流程。补充建议剩余十项保留在原文供复议。跨赛事业务数据批量导入、申诉/重赛、公共结果另行发布快照、通用 API 改版等均未进入本次排期。补充阶段仅采用用户已选的第 1、4、6、13、15 项。

- [ ] 复用现有备份、恢复和手动清理流程。验证仍被当届或往届引用的文件得到保护，保留 D8 的默认保留与人工清理政策。

### 第 13 项　可访问性和移动端验收

- [ ] 在手机验证注册、登录、建队/入队、约赛、成绩和截图提交、结果与归档查询。在小屏上检查表格、弹窗、长名称与表单反馈。
- [ ] 用键盘操作关键路径，检查焦点、标签、图片替代文本、错误关联及可读的状态提示。状态同时以文字等方式表达。
- [ ] 在 Chrome、Edge、Safari、Firefox 的约定版本验证关键流程，记录实际测试的平台、视口与结果。

### 第 15 项　每届运营交接包

- [ ] 生成一份可查的赛事交接清单，关联已发布配置、规则、赛事、应用/schema/镜像版本、备份及恢复记录、导出、未结算清单、调整审计、历史数据待核对项及下一届待办。
- [ ] 交接材料按第 4 项控制访问，以引用现有批次和结果为主。填写管理员/裁判操作说明、已知问题和临时配置。若实际有争议处理记录，可作为交接说明附带。
- [ ] 用隔离环境模拟下一位管理员接手。按交接说明找到当届依据、恢复所需版本与数据，再配置并创建下一届。
