# 明日方舟 · 集成战略 比赛计分器

单文件网页版计分器，用于明日方舟「集成战略」类比赛的实时算分。**双击即可用**——不需要安装、不需要联网、不需要后端。

- 一个 `.html` 文件装下全部内容（HTML + CSS + JS），无任何外部依赖
- 手机 / 电脑浏览器自适应
- 加减分项规则可在页面里直接改，配置自动保存
- 明细可导出 CSV / JSON / 打印 PDF，配置可在多台设备之间同步

| 项目 | 说明 |
|---|---|
| 主程序 | [`集成战略计分器.html`](./集成战略计分器.html)（约 67 KB，单文件） |
| 需求文档 | [`需求.md`](./需求.md) |
| 运行环境 | 任意现代浏览器（Chrome / Edge / Firefox / Safari 的近年版本） |
| 依赖 | 无（无 npm 包、无 CDN、无构建步骤） |

## 快速开始

1. 把 `集成战略计分器.html` 下载到本地（或部署到网站，见[部署](#部署到网站)）。
2. 双击文件，用浏览器打开。
3. 填比赛名称 / 选手或队伍 / 日期（这几项只用于导出文件抬头，可选）。
4. 依次填写四个分区，右上角「最终得分」实时刷新。
5. 算完点「导出 CSV」或「打印 / 导出 PDF」交给主办方；点「清空计分」开始下一位选手。

> 计分输入**不会自动保存**，刷新页面即清零（这是刻意的，避免上一位选手的数据残留到下一位）。需要留档请用导出按钮。

## 计分规则（默认值）

最终得分 = 原始分 + 基础结算加分 + 关卡加分 + 额外加分 − 扣分项合计

| 分区 | 条目 | 类型 | 默认分值 |
|---|---|---|---|
| **基础结算** | 原始分 | 输入型 | 直接计入总分 |
| | 用时（小时） | 时段规则 | `0~2h` +30；`2~4h` 0；超 4h 每超 1h −20 |
| | 藏品数量 | 输入型 | 每个 +5 |
| **关卡加分** | 无效验尸 | 勾选型 | +200 |
| | 同域共存 | 勾选型 | +300 |
| **额外加分** | 携带特殊藏品 | 勾选型 | +100 |
| | 六星 / 五星 / 四星（临时招募） | 输入型 | 每个 +50 / +20 / +10 |
| **扣分项** | 取钱超过 100 锭 | 阈值型 | 超出 100 锭的部分每锭 −10，即 `(数量 − 100) × −10` |
| | 携带特殊藏品 | 勾选型 | −100 |

界面上的约定：

- 加分为绿色、扣分为红色；每个分区标题右侧显示「本区小计」。
- 用时**区间含两端、按顺序优先命中**，所以恰好 2 小时算 `+30`；超时段部分默认「不足 1 小时按 1 小时计」（可改为按实际小数计算）。
- 用时**留空表示不计分**，不会被当成 0 小时。
- 数量类输入不接受负数：按 `-` 会被直接拦下；若从别处粘贴进负数，会被改写成「最低值」并高亮提示（默认最低值 0）。
- 数字输入会自动归一化：全角数字 `１，５`、中文句号 `3。5`、以及误输入的字母 `abc9x8` 都会变成可计算的数字；被自动纠正时输入框会短暂变黄。

## 配置模式

每个分区标题旁的「修改配置」进入该分区的编辑界面，**其他分区继续正常计分**，且本区已填写的输入会保留（点「保存」后继续有效）。

配置界面提供：

- **添加条目 / 删除条目 / 上移下移**排序
- 编辑**名称、类型、分值、分组、单位、阈值、最低值**
- 「恢复默认」（恢复该分区默认值，点保存才生效）、「保存」、「取消」

### 四种条目类型

| 类型 | 计算方式 |
|---|---|
| 勾选型 `check` | 勾选即加/扣该分值 |
| 输入型 `number` | 数量 × 分值 |
| 固定型 `fixed` | 恒定加/扣该分值（无需输入） |
| 阈值型 `threshold` | `max(0, 数量 − 阈值) × 分值` |

「分组」用于在计分界面显示小标题（如「临时招募」），留空表示不分组。「最低值」是数量下限，默认 0；确实需要负数量时把它改小即可（此时该输入框也允许输入负号）。

配置改动保存后立即生效，并自动写入浏览器本地存储（`localStorage`），下次打开仍在。

## 导出与导入

工具栏共 8 个操作：

| 按钮 | 作用 | 文件 |
|---|---|---|
| 导出 CSV | 完整明细：比赛信息、逐条明细（名称 / 数量或勾选 / 单位分值 / 小计）、加分合计、扣分合计、最终得分 | `计分明细_<选手>_<日期>.csv` |
| 导出 JSON | 备份：当前配置 + 当前计分输入 + 结算结果 | `计分明细_<选手>_<日期>.json` |
| 导入 JSON | 还原上一条导出的备份（覆盖现有配置与输入，有确认提示） | — |
| 导出配置 | **只**导出四个分区的配置 | `计分配置_<选手>_<日期>.json` |
| 导入配置 | **只**覆盖配置，已填写的计分输入按条目 id 保留 | — |
| 导出定制 HTML | 导出「自带当前配置」的 HTML 副本，换设备打开即生效 | `定制版计分器_<选手>_<日期>.html` |
| 打印 / 导出 PDF | 只打印**计分明细报表**（不是页面本身），浏览器里选「另存为 PDF」即可 | — |
| 清空计分 | 清空所有输入（有确认提示），配置不动 | — |

细节：

- CSV 带 BOM，Excel 打开中文不乱码。
- CSV 防公式注入：以 `=`、`+`、`-`、`@`、制表符、回车开头且**不是纯数字**的文本会前置一个 `'`，避免条目名被 Excel 当公式执行；`-200`、`+30` 这类分值仍按数值输出。
- 明细包含**未勾选**的条目（标记为「未勾选」），便于复核；未填写的数量显示为 `—`。

## 跨设备 / 跨浏览器

配置默认只存在**本机的这个浏览器**里（`localStorage` 按「浏览器 + 来源」隔离），换设备或换浏览器都读不到。两种搬运方式：

| 场景 | 用什么 |
|---|---|
| 想把**规则连同文件**一起给别人，对方打开就能用 | 「导出定制 HTML」，把生成的 HTML 发给对方 |
| 比赛现场多台设备要同步规则，但各自录不同选手的数据 | 「导出配置」→ 对方「导入配置」（不覆盖对方已填的数据） |
| 换电脑继续算同一位选手 | 「导出 JSON」→ 新电脑「导入 JSON」 |

内嵌配置的优先级规则（避免「拷来拷去把自己改的配置弄丢」）：

- HTML 里内嵌的配置（`<script id="default-config">`）与上次在本机生效的不是同一份（指纹不同）时，**内嵌配置优先**；
- 同一份文件再次打开，**仍以本机存档为准**，保留你在本机的改动。

## 数据存储与安全

### 存在哪里

| 键名 | 内容 |
|---|---|
| `arknights-ir-score-calculator.config.v1` | 四个分区的配置 |
| `arknights-ir-score-calculator.config.v1.embedded` | 上次生效的内嵌配置指纹 |

计分输入、比赛名称、选手名**一律不写入**本地存储。配置含 `version` 字段：存档版本与默认配置不一致时会自动按新默认值重建（改默认值请记得 `version + 1`）。

### 已内置的防护

- **导入内容白名单化**：外部 JSON / 内嵌配置里的条目 `type` 会被归一化为四种合法类型之一，不会进入 DOM 或计分逻辑。
- **输出转义**：条目名、分区标题、单位、标签等所有用户可编辑文本在渲染进页面、打印报表时均做 HTML 转义。
- **CSV 公式注入防护**（见上）。
- **导出定制 HTML 时**把内嵌 JSON 中的 `<` 转义为 `\u003c`，配置内容无法破坏脚本块。
- **无网络行为**：文件内没有任何 `fetch` / `XHR` / `postMessage` / 动态脚本加载，纯离线运行。

### 使用建议

计分器本身不适合作为唯一的成绩凭证——它是**辅助工具**，最终成绩请以导出的明细留档为准。接收到他人提供的配置文件或定制 HTML 时，应视为「不可信输入」（代码已做归一化，但仍建议只接收来自可信来源的文件）。

## 部署到网站

静态托管即可，无需任何服务端配置：

- **GitHub Pages**：把文件（建议改名为 `index.html`）推到仓库 → Settings → Pages → 选择分支目录
- **Cloudflare Pages / Netlify / Vercel**：直接拖拽文件上传
- **对象存储静态托管**：阿里云 OSS / 腾讯云 COS / 七牛，开启「静态网站」功能
- **自有服务器**：放进 Nginx / Apache 的静态目录

注意事项：

1. 线上域名与 `file://` 是不同的存储来源，**之前本机存的配置不会自动带过去**——上线前先「导出定制 HTML」或「导出配置」。
2. 文件名建议用 ASCII（如 `index.html`），否则 URL 会变成一长串百分号编码。
3. 同一域名下不要放多套不同规则的副本：`localStorage` 按来源共享，`/a/` 和 `/b/` 会互相覆盖配置。需要隔离请用不同子域名。
4. 服务端返回 `Content-Type: text/html; charset=utf-8`（文件内已有 `<meta charset="utf-8">`）。
5. HTTPS 下的本地存储比 `file://` 更可靠（部分浏览器对 `file://` 存储限制较多）。

## 开发说明

### 代码结构

独立 HTML 内嵌共享计分脚本和离线工具脚本。计分、录入控件与实时预览的源文件为 [score-calculator.js](../app/static/calculator/score-calculator.js)。修改后从仓库根目录运行 `python arknights-score-calculator/sync_shared.py` 更新独立 HTML，`--check` 可检查同步状态。

离线工具脚本按功能划分如下。

| 区段 | 内容 |
|---|---|
| 配置对象 | `BUILTIN_CONFIG`——**改默认规则就改这里** |
| 内嵌配置 | `EMBEDDED_CONFIG` / `DEFAULT_CONFIG` / `ITEM_TYPES` |
| 持久化 | `normalizeItems`、`mergeConfig`、`loadConfig`、`saveConfig`、`embeddedSignature` |
| 工具函数 | `esc`、`r2`、`signed`、`timeHint` |
| 渲染 | `render`、`sectionShell`、`itemHtml`、`basicBodyHtml`、`bindAll` |
| 计算 | `computeTotals`、`updateScores` 调用共享脚本 |
| 配置模式 | `enterEdit`、`readGroups`、`readBasicEditor`、`saveEdit`、`restoreValues` 等 |
| 导出 / 导入 | `collectRows`、`buildCsv`、`buildJson`、`buildConfigJson`、`buildCustomHtml`、`buildPrintSheet` |
| 事件与启动 | `keydown` / `input` / `change` / `click` 委托，`render()` |

设计要点：

- **页面结构只渲染一次**，之后只更新小计/合计的文本节点，避免输入时丢焦点。
- 进入配置模式时，本区计分 DOM 只是隐藏而不销毁，所以总分不会跳动。
- 输入用 `type="text"` + `inputmode="decimal"` 配合 `normalizeNumeric()` 归一化，而不是 `type="number"`（后者会静默丢弃 `1,5`、`1。5` 这类输入）。

### 修改默认规则

1. 改 `BUILTIN_CONFIG` 里的数值/条目；
2. **把 `version` 加 1**（否则用户浏览器里已保存的旧配置会覆盖新默认值）；
3. 打开页面确认「恢复默认」拿到的是新值。

### 调试接口

页面暴露了 `window.__scoring`，方便在 DevTools 控制台里检查与扩展：

```js
__scoring.computeTotals()      // 当前各项合计与最终得分
__scoring.config               // 当前生效的配置
__scoring.collectRows()        // 明细行（导出用的中间结构）
__scoring.buildCsv()           // 预览 CSV 文本
__scoring.buildCustomHtml()    // 预览定制 HTML 全文
__scoring.setMeta({player:'X', title:'Y'})
__scoring.resetConfig()        // 清除本机存档并恢复默认
```

### 测试

计分逻辑有一套配套测试：在 Node 里跑**从 HTML 抽出的真实页面脚本**（配最小 DOM / localStorage 桩），用例覆盖计分规则、边界值、导入导出、内嵌配置、打印报表等。

> ⚠️ 这套脚本目前**不在项目目录里**，位于系统临时目录（`%TEMP%`），因此在版本管理/交接时需要单独拷贝。

| 文件 | 作用 |
|---|---|
| `scoring-extract.js` | 从 HTML 抽出的页面脚本（**改了 HTML 后需要重新抽取**） |
| `scoring-stub.js` | 最小 DOM / localStorage 桩，支持「重新打开页面」 |
| `scoring-tests.js` | 用例主体 |
| `scoring-run.js` | 运行入口，报告写入 `scoring-report.txt` |
| `scoring-debug.js` / `scoring-run-debug.js` / `scoring-debug.txt` | 调试用的小脚本与输出 |

运行方式（PowerShell）：

```powershell
node "$env:TEMP\scoring-run.js"
```

改动计分逻辑后的正确流程：把当前 HTML 中最后一个 `<script>` 块重新抽取覆盖 `scoring-extract.js`（**不要沿用旧快照，否则测的是旧代码**），再运行一次，确认全部用例通过。

覆盖的典型场景：空表单、用时各时段边界（含 2h 恰好命中、4.5h、负值）、阈值型边界、输入归一化（全角/逗号/杂字符）、勾选与取消、CSV 的 BOM 与明细、JSON 往返、配置版本迁移、内嵌配置优先级与损坏回退、定制 HTML 往返、固定型与最低值、打印报表转义。

## 常见问题

**换台电脑打开，配置没了？**
配置只存在浏览器本地。用「导出定制 HTML」把配置写进文件，或「导出配置 / 导入配置」。

**刷新页面数据清零了？**
这是有意设计（选手之间不串数据）。需要留档请用导出。

**导出的 CSV 在 Excel 里是乱码？**
文件已加 BOM，正常不会乱码。若仍异常，请用 Excel 的「数据 → 从文本/CSV」导入并指定 UTF-8。

**打印出来是空白页？**
打印走的是专门的明细报表（`.app` 在 `@media print` 里被隐藏）。请用页面上的「打印 / 导出 PDF」按钮，或确认浏览器支持 `beforeprint` 事件。

**两个浏览器打开同一个文件，配置不一样？**
正常。`localStorage` 按浏览器隔离，用导出 / 导入同步。

**能不能嵌到别的网站、把成绩直接传进对方数据库？**
当前文件是纯离线的，没有任何 `postMessage` / 网络代码。若要嵌入并按 `postMessage` 交给主站落库，需要额外加：提交按钮 + `postMessage` 收发 + 父页面校验（来源白名单、身份由父页面提供、服务端重算分数）。`window.__scoring` 已导出 `computeTotals` / `buildJson` / `collectRows` / `metaOf`，接入时代码量很小。

**能离线用吗？**
可以，全程无需联网。
